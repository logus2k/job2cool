\subsection*{A\quad Running the system and reproducibility}

\begin{verbatim}
# Backend + baked frontend (deployed against the shared stack)
docker compose up -d --build job2cool-backend

# Candidate ingestion (isolated venv, idempotent, resumable)
python3 -m venv scripts/.venv-ingest
scripts/.venv-ingest/bin/pip install -r scripts/requirements-ingest.txt
scripts/.venv-ingest/bin/python scripts/ingest_candidates.py   # full 210k
#   --limit N   smoke-test with N rows
\end{verbatim}

Full features (including audio) are at \verb|https://logus2k.com/job2cool|; base features at
\verb|http://localhost:4920|. A one-time prerequisite for the ingest is the embedder
slot-cap (\verb|"parallel": 1| in \verb|agent_server/data/agent_config.json|,
Section~\ref{sec:perf}), without which a concurrent-load run can OOM the host.

\paragraph{Connection to the A1/A2 artifacts.} The A1/A2 work lives at
\verb|~/env/iscte/atlm_pro/outputs/|: A1 is the merged LoRA checkpoint
(\verb|mp1-360m/merged/|, seed 42), and A2 the DPO deliverable (\verb|ma2-360m-dpo-b01/|).
job2cool consumes the A2 model as a served, quantised GGUF on \verb|agent_server|,
referenced via \verb|JOB2COOL_DPO_MODEL|, so the chain from raw SmolLM2-360M, to the A1
merge, to A2 DPO, to the served drafter is explicit and traceable.

\paragraph{Seeds and reproducibility note.} A1/A2 training used seed 42 throughout; GPU
training is not bit-for-bit deterministic (under 1\% perplexity variance observed). The
ingest record IDs are deterministic (\verb|cand-{uuid}|), so the 210,048-CV corpus
reproduces from the same Parquet plus the documented sub-50-character drop rule. Two
components cannot be replicated exactly: the judge is an LLM (\verb|gemma-4| with a JSON
rubric), so its scores are not bit-exact and it judges its own output, an auxiliary signal
that is not in the generation path; and quantised inference and model-router residency are
not bit-for-bit reproducible, though the slot-cap bounds memory deterministically.

\subsection*{B\quad Backend-owned API surface}

\verb|job2cool-backend| owns these prefixes; everything else proxies to
\verb|kb-service| or \verb|noted|:

\begin{itemize}
  \item \verb|POST /api/chat| (SSE orchestration)
  \item \verb|GET /api/buffers/events/stream| and \verb|POST /api/buffers/{id}/save| (stub)
  \item \verb|GET /api/citation/{tag}|
  \item \verb|POST /api/graph_trace| and \verb|POST /api/score_answer|
  \item \verb|GET /api/job2cool/me| (authenticated identity)
  \item \verb|GET|, \verb|PUT|, \verb|PATCH|, \verb|DELETE| on \verb|/api/job2cool/chats[/{id}]| (Projects)
  \item \verb|GET /api/job2cool/candidates[/{id}]| (browse, search, detail)
  \item \verb|/api/agents/*| and \verb|/api/mcp/*| (presets; tools and skills)
\end{itemize}

The two additive \verb|noted-rag| endpoints built for the candidate ingest (copy-only
respected) are \verb|POST /upsert_records| and \verb|POST /list_records|.
